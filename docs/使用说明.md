# AI Workflow 使用说明

本文档面向最终用户，介绍应用的完整操作流程。

## 1. 界面总览

应用由**顶栏 + 主区域 + 底部药丸导航**组成，共 6 个视图：

| 视图 | 用途 |
| --- | --- |
| 🏠 首页 | 项目列表：新建 / 打开 / 复制 / 重命名 / 删除项目 |
| 📐 编辑器 | 三栏布局：节点面板（左）+ 画布（中）+ 配置面板（右），底部运行面板 |
| 🖥️ 模型 | 管理 LLM 模型配置（OpenAI 兼容接口） |
| 📄 提示词 | 提示词模板库：创建 / 分类 / 收藏 / 渲染预览 |
| 📜 日志 | 历史执行记录与节点级结果详情 |
| ⚙️ 设置 | 外观主题、语言、调试开关、默认超时等 |

> 「编辑器」Tab 需要先在首页打开或新建一个项目，否则不可用（点击会提示）。

## 2. 快速开始（3 分钟）

### 2.1 配置模型（必需）

1. 底部导航 → **模型**
2. 点击 **添加模型**，选择提供商（OpenAI / DeepSeek / 通义千问 / Kimi / 自定义），Base URL 与模型名会自动填充
3. 填入 **API Key**（使用系统安全存储加密，前端不保留明文）
4. 点击 **测试** 验证连通性
5. 点击 **设为默认**——LLM 节点不指定模型时自动使用默认模型

常用提供商参数：

| 提供商 | Base URL | 示例模型 |
| --- | --- | --- |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 自定义 | 任意 OpenAI 兼容端点 | 按需填写 |

### 2.2 创建项目

1. 底部导航 → **首页** → **新建项目**
2. 选择模板：
   - **空白工作流**：从零开始
   - **LLM 对话示例**：手动触发 → LLM 调用（体验流式输出）
   - **RAG 问答示例**：文档入库 → 向量检索 → LLM 回答
   - **文本流水线示例**：LLM 总结 → 文本处理 → 文件写入
3. 填写项目名称，点击 **创建并打开**

### 2.3 运行第一个工作流

1. 从左侧节点面板**拖拽**「手动触发」到画布，再拖入「LLM 调用」
2. 从触发节点底部输出口**拖线**连接到 LLM 节点
3. 点击 LLM 节点，在右侧配置面板填写提示词（可留空使用默认模型）
4. 点击工具栏 **运行** 按钮
5. 底部运行面板实时显示日志与流式输出，节点变绿表示成功

## 3. 编辑器详解

### 3.1 三栏布局

- **左栏 · 节点面板**：按 6 大类别分组的 16 种节点，支持关键字搜索；**双击节点条目**直接添加到画布中心
- **中栏 · 画布**：自由拖拽节点、连线；缩放（Ctrl+滚轮）、平移（空格拖拽或中键）、框选（拖空白区域）、迷你地图（右下角）
- **右栏 · 配置面板**：点击节点即显示；schema 驱动渲染表单；底部「引用上游输出」列出直接上游节点可引用字段，点击自动插入 `{{nodeId.field}}` 到正在编辑的文本框
- **底部 · 运行面板**：日志 / 流式输出两个 Tab，可折叠

### 3.2 快捷键

| 快捷键 | 功能 |
| --- | --- |
| `Ctrl/⌘ + Z` / `Ctrl/⌘ + Y` | 撤销 / 重做 |
| `Ctrl/⌘ + C` / `Ctrl/⌘ + V` | 复制 / 粘贴选中节点（含连线） |
| `Ctrl/⌘ + D` | 克隆选中节点 |
| `Delete / Backspace` | 删除选中节点 |
| `Ctrl/⌘ + S` | 保存到项目库 |
| `Ctrl/⌘ + L` | 自动布局（按依赖层级横向排列） |
| 双击节点 | 打开配置面板 |
| `Esc` | 取消选中 |

### 3.3 工具栏

- 撤销 / 重做（无历史时禁用）
- 自动布局：一键整理杂乱画布
- 导入 / 导出 JSON：跨机器迁移工作流
- 清空画布（二次确认）
- 全局变量：配置 `{{global.KEY}}` 变量表
- 运行 / 停止：执行与中断

> 离开编辑器时自动保存；也可随时点击顶栏「保存」。

## 4. 节点使用指南

### 4.1 LLM 调用（🤖）

- **模型配置**：留空 = 默认模型；也可指定具体模型
- **流式输出**：开启后在运行面板实时显示回复
- 输出字段：`text`（回复）、`model`、`usage`（Token 用量）、`duration`

### 4.2 条件分支（🔀）

- 支持等于 / 不等于 / 包含 / 大于 / 小于 / 为空 / 不为空等九种运算符
- 节点有两个输出口（True / False），连线时从对应出口拖出
- 输出字段：`result`（布尔）、`branch`（命中分支）

### 4.3 循环（🔁）

- `itemsSource` 引用上游数组输出（如 `{{http1.data.items}}`）
- 模板内可使用 `{{item}}`、`{{item.field}}`、`{{index}}`、`{{count}}`
- 输出：`results`（逐项结果数组）

### 4.4 子工作流（📂）

- 在 `workflowJson` 中粘贴完整工作流 JSON（与导出格式一致）
- 子流程内可通过 `{{global.sub_input}}` 读取父级传入的输入
- 子流程共享父级全局变量，执行中断会联动取消

### 4.5 工具调用（🛠️）

- **内置工具**：HTTP GET / POST、当前时间、数学计算、UUID 生成
- **MCP 服务器**：填写启动命令与参数（如 `npx -y @modelcontextprotocol/server-everything`）或 SSE 地址

### 4.6 RAG 链路（📚 + 🎯）

典型链路：`文档入库 → 向量检索 → LLM 调用`

1. **文档入库**：选择内容来源（直接文本 / 本地文件），设置分块大小与重叠
2. **向量检索**：`query` 填问题（可用 `{{上一步输出}}`），`topK` 返回条数
3. **LLM 调用**：用户提示词引用 `{{检索节点.combined}}` 作为上下文

### 4.7 代码执行（💻）

```js
// 上游数据在 input 变量中，用 return 返回对象作为输出
const upper = String(input).toUpperCase();
return { text: upper, length: upper.length };
```

## 5. 运行与调试

- **节点高亮**：运行中（琥珀色呼吸）、成功（绿色）、失败（红色）、取消（灰色）
- **运行面板 · 日志**：每条记录含时间戳、节点名、消息；带输出的条目可点击展开查看 JSON
- **运行面板 · 流式输出**：LLM 回复逐字显示，显示已累计字符数
- **日志页**：查看历史执行（成功/失败/耗时统计），点击记录展开每个节点的输入输出详情
- **失败排查**：节点配置错误会在日志中显示具体原因（如模型未配置、JSON 解析失败等）

## 6. 提示词库

1. **提示词** 视图 → **新建模板**，内容中使用 `{{varName}}` 占位符
2. 自动解析变量标签；按分类 / 收藏 / 关键词筛选
3. 点击 **渲染** 填写变量值实时预览结果
4. 复制按钮一键复制模板内容到剪贴板

## 7. 常见问题（FAQ）

**Q：运行时报「未配置模型」？**
A：LLM 节点留空模型时使用默认模型。请到「模型」页添加配置并设为默认；若指定了模型，请检查该模型是否已配置 API Key。

**Q：RAG 检索结果为空？**
A：确认文档已成功入库（日志中 `chunkCount` > 0）；尝试降低「最低相似度」阈值或增大 `topK`。

**Q：数据存在哪里？**
A：全部本地存储：`%APPDATA%/ai-workflow/`（项目、模型、提示词、历史、设置、向量库）。卸载应用前请备份该目录。

**Q：如何迁移工作流到另一台电脑？**
A：在编辑器中点击工具栏「导出 JSON」，在另一台机器「导入 JSON」即可；模型配置需在新机器重新添加。

**Q：执行历史不见了？**
A：检查「设置 → 保存执行历史」是否开启；该开关关闭后不再记录新执行。
